# Sentinel QA Notes

Date: 2026-08-15

## Core flow results

The public landing page loaded at the managed preview URL with the Sentinel hero, method section, trust links, and live workspace visible. The initial page rendered with no visible error state.

The intent compiler accepted a changed request for a $750, 45-day strategy with a 15% volatility phrase. Clicking **Compile guardrails** updated the capital amount and duration, preserved the structured policy display, and showed the success toast “Intent compiled into editable guardrails.”

The comparison panel displayed three Orion agents in policy-fit order with rank markers and visible intelligence, TVL, uptime, audit status, volatility, liquidity, and six check indicators. Selecting **Aura Engine** changed the active decision to “Approve with Warning” and updated the execution preview and evidence list.

The simulation toggle removed the simulated execution preview when switched off and restored the preview when switched on. The restored state visibly displayed **SIMULATED**, **NO FUNDS MOVED**, expected output, bridge flow, and failure conditions.

Opening **View audit report** displayed the full reasoning trace. The report contained the live user intent, current policy object, selected Orion agent, evaluated policy-fit score, all six checks, final verdict, recommendation, and simulation/live-review labeling. **Copy** produced the toast “Audit report copied to clipboard.” **Export .txt** produced the toast “Plain-text report exported.”

## Console and network observations

The browser console contained only expected debug, Vite connection, and React DevTools informational messages. No error or warning entries were observed during the exercised flows. Network activity showed successful analytics POST requests with HTTP 200 responses and no failed application requests. The interaction flow is client-side for the demo workspace, so no unexpected API calls were generated by compiling, editing, selecting, copying, or exporting.

## Scope note

A direct browser edit changed the capital-at-risk control from $750 to $900. The policy object, guardrail display, audit report, and simulated expected output updated to reflect $900 without requiring a new intent compile.

A second real guardrail edit changed the max weekly volatility slider from 10% to 15%. Aura Engine’s live evidence changed from **4/6 passed** with a weekly-volatility warning to **5/6 passed** with a passing explanation: “Observed volatility is inside the user-defined range.” The final verdict appropriately remained **Approve with Warning** because the audit remained in review; the audit warning stayed visible and transparent. The evaluated policy-fit score also increased from 80/100 to 84/100.

For the complete simulation transition, the workspace was first in simulation mode with a visible simulated execution preview. Toggling simulation off removed the preview and changed the report mode to **LIVE REVIEW**. Toggling it back on restored the preview with **SIMULATED**, **NO FUNDS MOVED**, expected output of approximately $920.08, the Base → Ethereum bridge flow, and circuit-breaker failure condition. The audit report mode changed back to **SIMULATION — NO FUNDS MOVED**.

The Orion agent metrics in the demo are clearly presented as simulated/demo values. Sentinel does not custody funds and does not execute transactions.
